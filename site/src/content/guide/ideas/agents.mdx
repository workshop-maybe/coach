In this app, an agent is one setup you run outside it: a harness such as Claude Code, Codex or Cursor, a model, an effort level, and the repo and parameters it works with. The same model at two effort levels is two agents, because the two can do different work.

## Why setups, not models

You probably already run several setups: this model, at this effort, opened in that repo. Some are good at some things and not others. Testing each setup on your own work tells you which one to reach for, and when a cheaper one is enough.

## The dials

You set an agent up on one card, with a dial for each setting: <UI>Harness</UI>, <UI>Model</UI> and <UI>Effort</UI>, and <UI>Version</UI> for models that have versions. If yours isn't listed, turn the dial to <UI>Other</UI> and type it. While an agent uses a model you typed, the model dial offers it again for that harness.

The app names a new agent for its setup. Later you can open it from home and fill in its other parts:

- <UI>Name</UI>: what you call it.
- <UI>Repo</UI>: the folder it opens in.
- <UI>Notes</UI>: anything worth remembering about it.
- <UI>Parameters</UI>: any other settings it runs with.

## A setup locks once it has a result

Once an agent has a result, its harness, model and effort lock, so every result stays tied to the setup that produced it. To try another model or effort, open the agent and click <UI>Make a new agent like this</UI>.

## You run the agent, not the app

The app never talks to your agents. It writes the prompt, and you carry it: copy a handoff, paste it into the agent, run it the way you always do, and paste the reply back.
